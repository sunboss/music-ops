# R-Music · 全新 AI 音乐系统

> 线上：`https://music.1234r.com`　|　代码：`github.com/sunboss/music-ops`　|　运维智能体：`@music-ops`
>
> **一句话定位：这不是"给播放器打补丁"，而是一套自研的 AI 音乐系统 —— 客户端是全新重写的，
> 大脑是大模型，音源引擎是我们自己的多平台服务（Go）；三者是一件事，不是三件事拼装。**

---

## 0. 为什么叫"全新"，而不是"改造 YesPlayMusic"

本项目历史上确实从 YesPlayMusic（Vue2 预编译产物）+ nginx 注入定制脚本起步。**那个阶段已经结束。**

| 维度 | 旧形态（已废弃） | 现在 |
|---|---|---|
| 前端 | YesPlayMusic 预编译 4.3M，靠 `sub_filter` 注入 CSS/JS 改外观 | **自研前端**（Vue 3 + Vite + TS + Pinia + Tailwind），632K，Apple Music 极简风重写 |
| 音源 | 网易云官方直连为主，换源仅兜底 | **自有 Go 音源引擎为主力**（11 平台），见 §3 |
| AI | 无 | **AI 是调度大脑**：点歌/电台/续播/控制/选源终审/口味记忆，见 §4 |
| 交互 | 点歌 = 搜索框输入 | **一句话或语音**；无限电台自动续播；本地自动发现投屏 |
| 投屏 | 无（且云端够不到局域网） | **浏览器本地发现**（Safari → 系统 AirPlay 选择器），已实测出声 |

结论：现在线上跑的是一个**新系统**，旧站只是它的历史。

## 1. 系统分层

```
              ┌──────────── 客户端（自研前端，按设备能力自适应）────────────┐
              │  Safari/iOS：系统 AirPlay 发现     Chrome：Cast / 小菜单     │
              │  一句话 / 语音 · 无限电台 · 队列抽屉 · 音乐库 · 投屏         │
              └───────────────────────┬─────────────────────────────────────┘
                                      │ HTTPS
              ┌───────────────────────▼─────────────────────────────────────┐
              │ 边缘（东京 64.83.34.204）：Nginx + Cloudflare                │
              │  静态前端 · SPA 回退 · HTML 不缓存 · 资源内容哈希长缓存       │
              └───────────────────────┬─────────────────────────────────────┘
                                      │ /api/*
              ┌───────────────────────▼─────────────────────────────────────┐
              │ 编排层 music-enhancer（Python）：一切播放都过这里            │
              │  候选编排 → 取直链 → **整曲落盘校验**（时长/体积/容器）→ 交付 │
              │  AI 中枢（DeepSeek 直连）：意图/检索词/策展/选源终审/口味记忆 │
              │  Range 服务 · 防盗链 · 缓存双约束 · 巡检                     │
              └───────────┬─────────────────────────────────┬───────────────┘
                          │                                 │
       ┌──────────────────▼──────────────┐   ┌──────────────▼──────────────────┐
       │ 音源引擎（自有 Go 服务，国内 IP）│   │ 目录/元数据（网易云 API）        │
       │ 11 平台：酷我/QQ/酷狗/咪咕/千千/ │   │ 歌单/专辑/歌手/歌词/封面/推荐    │
       │ 汽水/5sing/JOOX/B站/jamendo      │   │ 只回答"有哪些歌"，不负责出声      │
       │ 严格匹配 + 时长体积双校验         │   └─────────────────────────────────┘
       └─────────────────────────────────┘
```

**关键界线（最容易忘的一条）**：

- **音源（能不能出声、出什么音质）由我们自己的 Go 服务决定**；网易云只当"目录"用。
- 网易云对未登录请求会压制部分歌手、对 VIP 曲只给 30 秒试听 —— 这不再是系统瓶颈，因为**音频不靠它**。
- 取不到音源必须**明确报错**：不占位音频、不伪造码率/体积/md5、不承诺"全部能播"。

---

## 2. 交付契约（不变项）

1. **只在字节上判成败**：拿到的文件必须真实解码、时长与元数据吻合（容差 8 秒）、体积与码率相符。
2. **版本不许串**：Live / Remix / 伴奏 / 翻唱 / DJ 版与录音室版本不是同一样东西，匹配必须有版本守卫。
3. **失败要响**：全平台取不到 → 明确"无可用音源"且可自查，不退回播放别的版本。
4. **一切播放走同一闸口**：官方、换源、AI 选源都经同一处落盘校验，不允许直通旁路。

## 3. 音源引擎（我们的 Go 服务）

基于 `go-music-dl`（AGPL-3.0）自研适配器，**原生部署在国内机**（原生国内 IP，避免跨境签名失败），东京侧只做转发与回退。

| 平台 | 能力 | 备注 |
|---|---|---|
| 酷我 kuwo | 搜索/直链 | 当前最稳的中文曲库 |
| QQ 音乐 qq | 搜索/直链 | 支持 FLAC |
| 酷狗 kugou | 搜索/直链 | 支持普通歌曲 FLAC |
| 咪咕 migu | 搜索/直链 | |
| 千千 qianqian | 搜索/直链 | |
| 汽水 soda | 搜索/直链 | 音频解密 |
| 5sing / JOOX / B站 / jamendo | 搜索/直链 | 补充曲库 |

适配器接口：

| 端点 | 作用 |
|---|---|
| `GET /resolve-best?name=&artist=&album=&duration=&sources=&loose=` | **主力原语**：按来源优先级取第一个严格匹配的真直链 |
| `GET /resolve` | 跨来源搜索 + 匹配报告（不取直链） |
| `GET /resolve-url?source=&id=` | 指定来源取直链 |
| `GET /fetch?url=` | 经该出口代抓音频 |

**来源优先级是运维参数**（`FALLBACK_SOURCES`），不是写死的常量；平台今天能不能用要用真实歌曲实测，不看文档承诺。

## 4. AI 层（大脑）

| 能力 | 端点 | 为什么非 AI 不可 |
|---|---|---|
| 一句话判断意图 | `POST /api/ai/ask` | `play / radio / continue / control` 四类意图，规则写不出来 |
| 自然语言点歌 | `GET /api/ai/query` | 把"深夜写代码听的"变成可检索条件 |
| 场景/情绪电台 | `GET /api/ai/radio` | 多路召回 + 对**真实可播歌单**取舍、排序、命名 |
| 无缝续播 | `GET /api/ai/continue` | 基于当前曲目推"相似但不重复"，播放不断档 |
| 跨语言选源终审 | 编排层内部 | 规则判不了 `周杰伦 = Jay Chou`，要在候选里挑同一录音同一版本 |
| 口味记忆 | 编排层内部 | 听满 30 秒算正面、3–20 秒切走算负面，注入后续提示词 |

**双保险**：大模型判意图，算术判合理性 —— 时长差 >35 秒、或候选带目标没有的版本标记，一律拒绝。

## 5. 投屏（按设备本地发现）

云端**够不到**家里的设备（服务器在东京，设备在局域网），所以由**打开页面的那台设备自己发现**：

- **Safari / iOS / macOS** → `webkitShowPlaybackTargetPicker()` 系统选择器（自带勾选），**已实测可投 HomePod / Apple TV**；
- **Chrome / Edge** → Remote Playback（Cast）；它看不到 AirPlay 设备，界面如实告知并指引用 Safari；
- **DLNA** → 浏览器不能发 SSDP 组播，需在**同一台设备**上跑小桥（`tools/dlna-bridge.py`）。实测本网络无 DLNA 渲染器（`192.168.1.1`/`.158` 都是华为网关），故暂无落点，代码保留。
- 点投屏图标**直接出设备勾选**，不弹中间页面。

---

## 6. 目录（元数据）这一层

歌单、专辑、歌手、歌词、封面、每日推荐仍来自网易云 API —— 它做目录好用，做音源不可靠。
**边界就是：目录可以靠它，出声不靠它。**（若将来也要换掉目录层，见 `docs/AI-MUSIC-SYSTEM.md` 的路线图。）

---

## 7. 运维

- 东京每 15 分钟本地巡检写 `data/health.log`；外部 cron 每 30 分钟巡检，**健康即静默**、同签名 2 小时内不重复打扰。
- 音频缓存双约束（400 文件 / 2GB）+ 磁盘水位联动；`/` 低于 8G 自动收紧。
- 静态资源内容哈希长缓存 + HTML `no-cache`；改前端只替换 `dist` 内容（保持目录 inode，零停机、一键回滚）。

## 8. 红线

- 密钥只从文件/环境变量读（`600`），不进代码、日志、仓库、聊天。
- 共享服务器上只清理我们自己的镜像/容器/缓存。
- 不伪造音源与元数据；找不到就说找不到。
