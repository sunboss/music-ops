# R-Music 前端重写方案

> 基于对线上站点的实测分析（路由表、真实接口调用、三档宽度截图）制定。
> 分析产物：`analysis/` 目录截图；接口清单来自 nginx 访问日志（2 万条）。

## 一、现状分析（实测）

### 1.1 技术栈与体量
- 线上是**别人的预编译产物**：Vue 2 + webpack + Workbox PWA，`dist/` 4.3MB
- 三个 chunk：`chunk-vendors` 565KB、`chunk-aad34c94` 391KB、`index` 172KB（未压缩）
- 仓库里**没有前端源码**，所有定制都靠 nginx `sub_filter` 注入（主题 CSS、Logo、注入脚本、AI 面板）
- 8 张样式表、**仅 23 条媒体查询规则** → 响应式形同虚设

### 1.2 路由表（19 个，运行时读取）
```
/                     首页
/login  /login/username  /login/account
/playlist/:id         歌单
/album/:id            专辑
/artist/:id  /artist/:id/mv  /mv/:id
/next                 播放队列
/search/:keywords?  /search/:keywords/:type
/new-album  /explore  /library  /library/liked-songs
/settings
/daily/songs          每日推荐
/lastfm/callback
```

### 1.3 前端真实调用的接口（按调用次数）
| 接口 | 次数 | 用途 |
|---|---|---|
| song/detail | 2286 | 歌曲元数据（**列表页重度依赖**） |
| lyric | 1411 | 歌词 |
| scrobble | 345 | 收听上报 |
| personal_fm | 159 | 私人 FM |
| search | 140 | 搜索 |
| client-report | 134 | 我们的客户端回报 |
| toplist/artist | 98 | 歌手榜 |
| playlist/detail | 95 | 歌单详情 |
| personalized | 95 | 每日推荐 |
| album | 94 | 专辑 |
| toplist | 90 | 排行榜 |
| audio/proxy | 89 | **我们的音频代理** |
| album/new | 87 | 新碟 |
| song/url | 60 | 取源 |
| artist/album | 53 | 歌手专辑 |
| ai/query 18 · ai/radio 16 | — | **我们的 AI 点歌/电台已在用** |

> 结论：重写必须完整兼容这些接口的字段（`ar/al/dt/privilege/fee`）与分页语义。

### 1.4 移动端：**基本不可用**（实拍证据）
390px 宽度下的问题：
1. 顶栏导航（首页/发现/音乐库）被挤掉，只剩一个"现"字露出
2. **没有任何播放控制**——没有底部播放条、没有悬浮控件，看不到在放什么
3. 歌单头部横向溢出：标题"欢…"被右边缘截断，`播放` 按钮只剩半个 ▶
4. 歌曲行三列挤压，专辑名列截断成 `THE…`、`Stephen…`
5. AI 按钮（`position:fixed; bottom:104px`）浮在列表中间，**压住歌曲行**
6. 首页卡片是桌面尺寸直接压缩：2 列巨图，一屏只能看 2 张
7. 无底部安全区适配、无下拉刷新、无手势

### 1.5 桌面端的问题（相对较好）
1. 歌单页出现**空白的"描述"标签**（无内容也渲染标签）
2. 歌曲列表**没有表头**，专辑名一列突兀地立在中间
3. 头部信息区左下方大片留白，视觉失衡
4. 纯白背景、无暗色模式；卡片信息密度低（1440 下 5 列）
5. 长标题不做优雅截断（`spiral (TV动画《无职转生II》…)` 一行拉满）

## 二、重写方案

### 2.1 技术选型（全部为当前主流版本）
| 层 | 选型 | 理由 |
|---|---|---|
| 构建 | **Vite 7** + TypeScript | 秒级 HMR、产物小、生态成熟 |
| 框架 | **Vue 3.5**（`<script setup>`） | 接口字段与现有前端同源，迁移语义零损耗 |
| 状态 | **Pinia** | 官方方案，播放器/Pinia 持久化用 `pinia-plugin-persistedstate` |
| 路由 | **Vue Router 4** | 保持现有 URL 结构（`/playlist/:id` 等），旧链接不失效 |
| 样式 | **Tailwind CSS v4** + 少量 CSS 变量 | 原子类保证一致性，主题切换只需换 token |
| 音频 | **Howler.js** | 已验证方案，跨端行为一致 |
| 列表 | **vue-virtual-scroller** | 歌单动辄 1000+ 首，必须虚拟滚动 |
| 图标 | **lucide-vue-next** | 线性统一，体积按需 |
| PWA | **vite-plugin-pwa**（Workbox） | 保留现有离线能力 |
| 工具 | **@vueuse/core** | 手势、媒体查询、持久化等 |

### 2.2 页面重组（19 路由 → 12 页面 + 3 抽屉）
**一级页面（移动端四个 Tab）**
1. **首页** — 每日推荐入口、推荐歌单、新碟
2. **发现** — 排行榜、歌单分类、歌手榜、新歌
3. **音乐库** — 登录、我的歌单、收藏、最近播放、本地
4. **AI 音乐**（升级为独立页）— 点歌 / 电台 / 口味 / 语音，把现在浮窗的能力内聚成页面

**二级页面**
5. 歌单详情（虚拟滚动 + 批量操作 + 表头可选）
6. 专辑详情
7. 歌手详情（热门歌 / 专辑 / MV / 简介）
8. 搜索（综合 / 单曲 / 专辑 / 歌手 / 歌单，分 Tab + 搜索历史与建议）
9. 每日推荐
10. 设置（音质、主题、AI、缓存、关于）
11. 登录（扫码 / 手机 / 邮箱）
12. MV 播放

**抽屉/全屏**
- 全屏播放器（封面 + 歌词 + 控制，移动端上滑、桌面端常驻右侧抽屉）
- 播放队列
- 歌曲操作菜单（下一首播放 / 收藏 / 下载 / 相似推荐）

### 2.3 设计系统（Design Token）
- **主题**：深色为主 + 浅色可切（音乐类应用主流，夜间使用多）
- **主色**：`--acc #5b8cff` → `--acc2 #a855f7` 渐变（沿用现有品牌色）
- **体积**：`--r 14px` 圆角、8pt 间距栅格
- **质感**：播放条/浮层用 `backdrop-filter: blur(18px)` 毛玻璃
- **字号**：标题 17/20，正文 13.5，次要 11.5；行高 1.5
- **状态**：骨架屏 / 空态 / 错误态 / 加载态四套统一组件
- **无障碍**：对比度 ≥4.5:1、键盘可达、`prefers-reduced-motion` 支持

### 2.4 响应式策略（断点行为，不是缩放）
| 断点 | 导航 | 播放器 | 内容 |
|---|---|---|---|
| **<640 手机** | 底部 Tab（4 入口）+ 顶栏仅标题与搜索 | 迷你条常驻 → 上滑全屏 | 单列/2 列栅格；歌曲行两行信息（专辑并入副标题） |
| **640–1024 平板** | 折叠侧栏（图标 + 抽屉展开） | 底部常驻播放条 | 3 列栅格；歌曲行隐藏专辑列 |
| **>1024 桌面** | 固定侧栏（含歌单快捷入口） | 底部常驻播放条 | 4–6 列自适应；歌曲行完整列 + 表头 |

**关键规则**
- 触控目标 ≥44px；底部留 `env(safe-area-inset-bottom)`
- 播放器为**全局单例**，路由切换绝不重建（现状路由跳转会打断播放的风险点）
- 图片 `loading=lazy` + 骨架占位，避免布局抖动

### 2.5 修掉现状的具体缺陷（验收清单）
- [ ] 移动端：底部 Tab + 迷你播放条 + 全屏播放器
- [ ] 移动端：歌单头部横排不截断，操作按钮完整可见
- [ ] 移动端：歌曲行不挤压，专辑名不再截成 `THE…`
- [ ] AI 入口不再遮挡列表（改成底部 Tab + 播放条按钮）
- [ ] 去掉空白的"描述"标签
- [ ] 列表加表头（桌面）/ 隐藏专辑列（手机）
- [ ] 头部信息区留白平衡
- [ ] 长标题优雅截断 + 悬停显示全名
- [ ] 深色模式 + 跟随系统
- [ ] 1000+ 首列表虚拟滚动不掉帧

### 2.6 实施路线（每阶段可验收）
| 阶段 | 内容 | 验收 |
|---|---|---|
| **P0** | 脚手架 + 设计系统 + 布局骨架（含移动底部 Tab）+ 播放器内核 + 数据层（API 封装） | 三档宽度截图；能播一首歌且路由切换不断播 |
| **P1** | 首页 / 歌单 / 专辑 / 歌手 / 搜索 | 真实浏览器 + 手机实测；对照旧站功能不缺失 |
| **P2** | 音乐库 / 每日推荐 / 发现 / 排行 / 设置 / 登录 | 同上 |
| **P3** | AI 音乐页（点歌/电台/口味/语音）+ 全屏播放器 + 歌词 | 复用现有后端，无接口改动 |
| **P4** | 打磨：动画、骨架屏、PWA、无障碍、性能预算 | Lighthouse ≥95；首屏 JS <150KB gzip |

### 2.7 部署与回滚
- 新增 `web/` 目录（Vite 工程），构建产物输出到 `dist/`
- **nginx 与 `/api` 代理完全不动**；AI/换源后端零改动
- 上线前 `dist` 备份为 `dist.bak.YYYYMMDD`，有问题一条命令回滚
- 旧注入脚本（主题/Logo/增强）逐步下线，逻辑内聚进组件

### 2.8 风险
| 风险 | 应对 |
|---|---|
| 接口字段不兼容 | P0 先做 API 适配层，用现有真实响应做契约测试 |
| 工作量（19 路由） | 分阶段交付，P0+P1 先做到"新站可用、旧站可回滚" |
| 登录/收藏等写操作 | 现状也未登录；先做只读浏览 + 播放，登录作为 P2 可选 |
| 播放中断回归 | 播放器单例 + 切换路由不断播的自动化测试 |
| 歌曲无源 | 沿用现有 `unplayable` 登记与灰色标记 |

## 三、建议

**先做 P0+P1**：交付一个"能用、好看、手机可用"的新站（首页/歌单/专辑/歌手/搜索 + 播放器），
保持旧站随时可回滚；确认方向后再推 P2–P4。

设计方向见同目录 `mockup-design.html`。
